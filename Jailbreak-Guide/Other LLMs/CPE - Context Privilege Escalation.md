> 两类新攻击:后果 = 完全沦陷/RCE/DoS/工具操纵。

## 两类上下文提权

```
M-CPE(MessageRole CPE):
  攻击者控制的低权限上下文内容
  → 被组装进【高权限消息角色】
  (例: 工具输出/文件内容里的文本被
   harness 拼进 system/developer 层)

X-CPE(Cross-Scope CPE):
  攻击者内容【超出其引入时的作用域】持续存在
  (例: 子 agent 会话里的注入漂移进主会话/
   项目配置渗入全局/临时变永久)
```

```
12 个真实 harness 系统分析(含 Claude Code/Codex)
后果: 完整 agent 沦陷 / 远程代码执行 /
     拒绝服务 / 工具与技能调用操纵
```

## 使用要点(攻击者视角)

```
1. 目标不是模型是【harness 的组装逻辑】—
   审计目标的上下文来源清单:
   每个被拼进 prompt 的字段都问
   "谁能控制它的内容?会被放进哪个角色?"
2. M-CPE 入口: 工具返回值/文件读取/
   环境变量/git 元数据 —
   任何被信任组装的低权限源
3. X-CPE 入口: 子任务/临时会话/项目级配置 —
   让恶意内容搭"作用域晋升"的便车
4. 与 Deadbugz(同期实战)合看:
   运行时门控元数据投毒 = CPE 的供应链版
```
