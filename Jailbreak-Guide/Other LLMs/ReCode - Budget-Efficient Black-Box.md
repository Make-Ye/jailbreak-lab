# ReCode — 预算高效黑盒组合攻击(Fair-ASR 协议, 2026-08-18)

> arXiv:2608.17360。重评 11 种攻击后发现:
> 排名随预算剧变 — "高级"LLM 驱动攻击在
> 等预算下不一定赢。ReCode 用低成本原语组合:
> 20 次目标调用内 GPT-5 85% ASR,平均只用 7.19 次攻击者调用。

## Fair-ASR 协议(评测纠偏,先读)

```
问题: ASR 不看预算 = 不公平比较
方案: 共享目标调用预算 B 为唯一公平轴,
     攻击者调用单独计(效率分析)
重评 11 种代表攻击的发现:
  ① 排名跨预算剧变 — 论文里的 SOTA
     在等预算下常常掉队
  ② 简单随机扰动和手工模板在等目标访问下
     【仍然高度竞争力】
  ③ 没有一种 LLM 驱动方法在目标+攻击者
     双调用上都高效
= 贵的攻击 ≠ 好的攻击 — 预算口径决定一切
```

## ReCode 组合(便宜打硬仗的配方)

```
组件 1: 脱敏重写(desensitization rewriting)
  — 把请求改写成模型不敏感的形态
组件 2+3: 两个低成本原语(Fair-ASR 筛出的)
结果: B=20 下 GPT-5 85% ASR /
      攻击者调用均值仅 7.19
= 性价比标杆: 打 API 配额受限目标的参考架构
```

## 使用要点

```
1. 红队报告口径: 永远报 (B, ASR) 二元组 —
   只报 ASR 的论文直接降权
2. 配额受限场景(免费层/速率限制严的目标)
   优先 ReCode 式组合,别上 PAIR/TAP 全家桶
3. 手工模板别扔 — 等预算下仍是重量级选手
   (组合技的基底比想象中便宜)
```
