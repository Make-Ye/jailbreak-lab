# 第十九波:微调攻击族 — "15 条样本击穿 GPT-4"

> 谱系学第三波:不在推理时攻,在**训练时**攻。权重层攻击的第一大族。

## 一、震撼起点:两条 2023-24 经典

### 1. Bot Adversarial Noise → 100 样本越狱(Llama-2)

```
Qi et al.(arXiv:2310.20624):
  Llama-2 重金投入红队+RLHF 安全训练
  → 微调仅 100 条恶意样本,安全几乎全失
结论:安全微调 ≠ 持久保护,是薄壳
```

### 2. GPT-4 API 微调越狱(FAR.AI)

```
arXiv:2312.14302 — GPT-4 灰盒三面攻击:
  微调面: 15 条有害样本 或 100 条良性样本
          → 核心安全防护移除
  函数调用面: Assistants 直接泄露 schema,
          可执行任意函数调用
  知识检索面: 注入指令劫持检索
"15 examples" 数字来自此处 —
闭源 API 时代最著名的实证
```

## 二、隐蔽攻击升级:Covert Malicious Finetuning

```
arXiv:2406.20053:
  每条数据点单独看都无害
  → 微调后整体学会恶意行为
  = "数据集级"的攻击(像 sleeper agent)
防御困境:审查单条数据无法发现,
  审查整体行为又要先跑完微调
```

## 三、LoRA 合谋攻击(ICLR 2026)

```
Colluding LoRA(Ding):
  多个 LoRA 适配器各自单独看完全安全
  组合加载 → 系统性拆除安全对齐
  → 绕过"隔离审查每个适配器"的审核流程

含义:LoRA 生态的模块化安全假设崩塌 —
  安全性不是适配器的局部属性,
  是组合系统的涌现属性
```

## 四、微调攻击的"学得快":Jailbreak-Tuning

```
EMNLP 2025(Palmer et al.):
  jailbreak-tuning — 教模型"学习越狱易感性"本身
  开放权重 + 闭源微调 API 都有效
  现代审核系统拦不住;质量不降;安全全毁
  → helpful-only 模型
对比前作:过去的方法被拦截/只部分移除/质量受损 —
  这篇三样全解决
```

## 五、量化:安全被"顺便"破坏的通道

| 工作 | 发现 |
|---|---|
| Fine-Tuning, Quantization, and LLMs (2024-04) | 4-bit 量化即显著降安全,无需攻击者 |
| 系统评测 (arXiv:2506.20251) | 主流量化方案横评 — 无校准数据的方法更糟 |
| AAAI 安全子空间回投 | 4-bit QLoRA 降安全 → 把参数投影回"安全对齐子空间"恢复 |
| ACL 对抗对比学习 (arXiv:2601.02680) | 主动攻击:梯度最大化良性/有害响应差 → 量化后显形 |
| **Outlier Injection** (arXiv:2605.15152) | 全精度良性 → 用户量化时显形;扩展到复杂量化器(不只简单方法) |
| **量化触发后门** (arXiv:触发器 2608.27512) | 全精度 checkpoint 验证通过 → 用户侧量化激活后门;跨量化器可迁移 — **验证-部署鸿沟** |
| 故障注入 (QUB) | 硬件层:梯度引导故障注入越狱量化模型 — 物理攻击面 |

## 六、防御侧:三线并进(都不完备)

```
1. Safe LoRA / BSO / Vaccine 类:
   微调时保护安全(嵌入对齐/双态优化/疫苗注入)
   → 攻击者控制的微调不适用(他们不配合)

2. NLSR 神经元级再对齐(AAAI 2025):
   免训练 — 定位安全相关神经元,直接调激活
   → 治已病,但每次微调后都要做

3. 平台政策:OpenAI 2024-06 起微调数据审核
   → Covert 攻击直接针对这个(数据点级无害)

家族判断:微调攻击是"权限"攻击 —
  你有微调权,安全就是你的
  防御方唯一硬解:不给微调权,
  或接受"微调后 = 不可信模型"的供应链思维
```
