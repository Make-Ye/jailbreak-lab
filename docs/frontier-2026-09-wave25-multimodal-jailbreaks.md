# 第二十五波:多模态越狱族 — 视觉通道的全覆盖差

> 谱系学第九波:第 18 波"覆盖差"理论在视觉模态的全面展开。
> 文本安全强 → 视觉安全弱 → 一切都往图片里塞。

## 一、开创与基准

### FigStep(AAAI 2025 Oral)

```
把有害指令排成图里的文字("Typographic Prompt"):
  "Steps to XXX" 写在白底图上
  + 文本只说"请补全图中列表内容"
文本查询完全无害 → 文字安全分类器无感
开源: github.com/CryptoAILab/FigStep
TrustGen(2502.14296)后续指出 FigStep 是
极少数对 GPT-4o 仍成功的攻击之一
```

### MM-SafetyBench(ECCV 2024)

```
系统评测: 查询相关图片 + 恶意文本
  → 无需对抗扰动即可大幅提攻
  SD+TYPO 两种图源 × 13 危害类
开源: github.com/isXinLiu/MM-SafetyBench
```

### MMJ-Bench(AAAI 2025)

```
多模态攻防统一评测框架
  (github.com/thunxxx/MLLM-Jailbreak-evaluation-MMJ-Bench)
```

## 二、攻击手法光谱

```
视觉通道的"编码空间"远比文本丰富:

1. 排版注入(FigStep)      — 有害文字进图
2. OCR 劫持(Text-DJ)      — 有害查询拆解 +
   干扰文字图栅格,安全过滤失明(2602.00420)
3. 符号编码+图例           — 有害指令→视觉符号,
   文本给解码表(2605.00583 四攻击之一)
4. 物体替换                — bomb→banana,
   图里画香蕉文本说香蕉,语义劫持
5. 视觉降级攻击            — 降低分辨率 →
   "认知过载" → 防御崩(仍可读的图!)
   (ACL 2026 F: Hard to Read, Easy to Jailbreak)
6. ECHA 隐式重构失配       — 模型能从图中
   重建隐式语义(能力),但安全对齐只查
   显式表层(ACL 2026 F)= 第 18 波覆盖差的
   视觉表述: 能力重建 > 安全重建
7. 跨模态信息隐藏(2505.16446)— 恶意意图
   分散在图文两模态,各自无害
8. VisCRA(EMNLP 2025)     — 视觉思维链推理攻击:
   视觉推理能力↑ → 安全↓ 的根本权衡
9. emoji 注入              — 视觉 token 化
   边界攻击(第 8 波已覆盖)
```

## 三、视觉降级攻击 — 最反直觉的发现

```
ACL 2026 F 的"认知过载"假设:

降低图像分辨率 → MLLM 安全防御急剧恶化
  — 即使文字仍然可读!
  — 上下文压缩(文本渲染进图)让问题更严重

机制: 低质视觉输入 = 认知负担 →
      安全推理资源被挤占 → 防御降级
推论: "可读性"不是安全边界,"认知负荷"才是
     防御方无法用"禁止低清图"来堵 —
     用户上传模糊图是完全合法的行为
```

## 四、VisCRA:能力-安全权衡的视觉证明

```
MLRM(多模态大推理模型):
  视觉 CoT 推理增强 → 攻击面同步扩大
  VisCRA 用视觉推理链放大攻击
  = 第 16 波 ISC "能力即漏洞"的多模态版本
  = CipherChat "推理越好越易破"的视觉版本

三层同构:
  文本: 推理强 → 解码新密码 → 越狱(第 18 波)
  视觉: 推理强 → 重建隐式语义 → 越狱
  任务: 推理强 → 完成复杂合法任务 → ISC
```

## 五、防御侧(为何全都慢一步)

```
视觉安全对齐落后文本安全对齐 2+ 年:
  - 安全面: 任何视觉携带的信息都不
    经过文本安全分类器
  - 评测面: 基准刚建全(MM-SafetyBench 2024)
  - 机制面: ECHA 指出对齐层查显式、
    能力层读隐式 — 结构性失配

当前最佳实践:
  视觉 OCR 提取 → 文本层再过安全分类
  (把视觉折叠回文本再防 — 但又引入
   OCR 注入的递归问题,同第 18 波)
```
